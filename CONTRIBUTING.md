# Contributing

Welcome! Follow README setup instructions, then choose a small issue. Propose large changes in an issue before implementing them. Small fixes can go straight to a pull request.

Beginner-friendly work: copy improvements, keyboard navigation checks, documentation and sample themes in `src/themes/index.ts`. Maintainers should label issues `good first issue` only when they include scope, relevant files and acceptance criteria. Use `help wanted` for community-ready work.

Run type checking, unit tests, a production build and relevant browser tests. New analytics require tests for empty data, date boundaries, ties and incomplete coverage, plus documented provenance. Never infer time-of-day personalities from daily calendars.

Themes require a name, background and accent. Validate contrast, mobile layouts, keyboard focus and reduced motion in the sample. Translations, charts and personalities are welcome proposals; keep unrelated changes separate.

After repository publication, enable GitHub Discussions for questions, ideas and showcases. Keep reproducible bugs in Issues. Never include tokens or private data in issues, fixtures or screenshots. Follow CODE_OF_CONDUCT.md.
